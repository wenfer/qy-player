# 运维说明

面向用户/运维的运行时说明。

## 1. 插件与刮削

- **TMDB**：设置 → 插件 中填入自己的 TMDB v4 Read Access Token（仅存
  SecretStore，可从设置页测试健康状态；401→需要重新配置，429→稍后重试）。
  Token 只走 Bearer 头，不出现在 URL/日志/缓存键。
- **刮削**：详情页「刮削元数据」单项；媒体库目录页「批量刮削」（≤500/批，
  并发 2）。置信度 ≥0.92 自动应用；0.75–0.92 进人工确认队列；<0.75 不动。
  人工锁定字段（元数据编辑器）永不被刮削覆盖。
- **任务页**（导航「刮削任务」）：进度、取消、失败后恢复剩余条目；
  上游结构变化（UPSTREAM_CHANGED）自动暂停整批，适配后可恢复。
- **豆瓣**：实验路径，默认关闭且**不可启用**（ADR-0006 发布门禁未签认）。
  UI 不出现豆瓣入口，零网络请求。人工产品/法律/技术评审通过前保持该状态。

## 2. 缓存

| 分区 | 位置 | 策略 | 清扫 |
|---|---|---|---|
| 技术信息 probe | 内存 | LRU + TTL 6h，按内容指纹失效 | 自动，失败永不缓存 |
| 插件响应 | `userData/scrape-cache/` | mtime-LRU（读即续命）+ TTL 7 天，4096 条 | 自动驱逐 |
| 音乐封面 | `userData/covers/` | 派生缓存，64MB 配额，mtime-LRU | `CacheManager.sweep`，删了按需重生成 |
| 离线频谱 | `userData/music-spectrum/` | 派生缓存，64MB 配额（≈460 首），mtime-LRU | 超配额时由服务触发一次 sweep；删了下次播放重算 |
| 图片 | `userData/images/` | mtime-LRU，配额清扫 | `CacheManager.sweep` |
| **歌词** | `userData/lyrics/` | 人工可编辑 | **受保护，永不清扫** |
| **人工字幕** | `userData/subtitles/<itemId>/` | — | **受保护，永不清扫** |

## 3. 并发与速率预算（常量单源 `cache-manager.ts`）

| 场景 | 上限 |
|---|---|
| 本地扫描 | 8 |
| WebDAV 扫描 | 4 |
| mpv probe | 1 |
| 刮削 | 2 |
| 离线频谱解码（ffmpeg） | 1 |
| 事件推送 | ≤4Hz |
| 列表单页 | ≤200 |

## 4. 续播与自动连播

- 续播规则单源：`playback-state/resume-resolver.ts`（30s 有效门槛、90% 完成、
  看完→下一集→重播；0/null 不覆盖历史）。
- 自动下一集：仅自然 EOF 触发，5s 倒计时可取消；设置 → 播放可关闭
  （`app_config playback.autoNext`）。手动停止/崩溃/断开/退出不触发。
- 「从头播放」显式 0 起播，不清除历史。

## 5. mpv 音源的离线频谱（可选依赖 ffmpeg）

- **为什么**：mpv 0.32 没有实时频谱接口（`audio-fft` 是 0.34+ 才有，升级会破坏
  老系统兼容），所以 APE/WMA/CUE、服务器转码这类音源以前只有一根静音底线。
  现在主进程在起播后**后台**用 ffmpeg 解一遍、算成「每 1/12 秒 × 48 频带」的
  矩阵（一首 4 分钟 ≈138KB），渲染层按播放进度回放。**声音仍由 mpv 播放**。
- **依赖**：先找 `~/.local/bin/ffmpeg`（与 mpv 同一处自建产物，见
  `docs/BUILD-MPV.md`），再找 PATH 上的 `ffmpeg`；都没有就静默降级（该曲目
  维持静音底线，不报错、不阻塞播放、本会话不再重试）。
- **代价**：并发 1、起播 3 秒后才开工、硬超时 90s、单文件上限 8MB、超过 2 小时
  的曲目直接跳过；换曲目立即取消（子进程 SIGKILL），退出时同步清理。
  设置 → 音乐可整体关闭（`playback.offlineSpectrum`，默认开）。
- **失败语义**：一切都静默——失败不进日志、不进诊断、不弹窗；URL 与认证头
  绝不落盘/落日志。

## 6. 音效链的开销（QYP3-068v）

- **内置引擎**（mp3/FLAC 直解等）在渲染进程的 Web Audio 图上做处理：10 个
  Biquad 段 + 4 增益声场矩阵 + 2 个交叉馈送低通 + 一个 WaveShaper。这些都是
  **实时音频路径上的必做工作**，`resource-guard` 的降帧保护（只降可视化刷新）
  管不到它——音频不能为了省 CPU 而"少处理几个样本"。
- **只在开启时才有代价**：总开关关闭 = 参数归直通值（增益 1、Biquad gain 0、
  单位矩阵、crossGain 0、`WaveShaper.curve = null`），节点常驻但不产生可闻/
  可测的处理量。节点永不重连、`AudioContext` 永不 close——避免爆音与图重建。
- **削波保护的 `oversample` 固定 `'none'`**：老机 CPU 上 4× 过采样不划算。
  代价是软削波本身会产生一点混叠，听感上比硬削波好得多，接受。
- **mpv 音源**的代价在 mpv 进程，改参数会重建整条 af 链并 flush 缓冲：主进程
  做了 120ms 防抖（拖动滑块期间最多每 120ms 重建一次），所以是"松手生效"。
  这一层防抖不能去掉——连续重建就是连续爆音。
- **面板打开时不做任何预计算**：软削波曲线按 ceiling 缓存（只有 13 个取值），
  频谱/波形拾取与音效链无关（采样点在 EQ 之前）。

## 7. 诊断摘要

诊断快照可安全分享：API key/token/凭据已打码；服务器地址只保留协议
（主机名整体 `***`）；缓存分区不出现绝对路径。导出前无需手工检查，
但如见异常字符串请反馈。

## 8. 回滚说明

- 数据库 migration 只追加不改写；回滚应用版本时旧库保持可读
  （schema_version 向前兼容由迁移数组尾部追加保证）。
- 插件缓存可整目录删除（`scrape-cache/`），下次刮削自动重建。
- 字幕目录删除即丢失人工字幕——删除前确认。
- 若 mpv probe 异常，probe 结果永不缓存失败，重启即重试；播放不受影响。
- 音效链配置是 `app_config` 的 `playback.audioFx` 一个 JSON 键；删掉即回到
  直通（旧键 `playback.eqGains` 保留不删，回滚到 1.4.x 也能读到旧的 10 段
  增益）。自定义预设在同表的 `playback.eqPresets`（旧格式会被自动升级）。
